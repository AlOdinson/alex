ALEX BOARD 0.9.7 — УСТАНОВКА

ПЕРЕД ОБНОВЛЕНИЕМ

1. Не очищайте данные браузера и IndexedDB: там могут находиться ещё не отправленные действия 0.9.6.
2. Закройте вкладки доски на всех устройствах. Ожидать опустошения старой медленной очереди необязательно: операции останутся в IndexedDB и будут отправлены новой версией пакетами.
3. Желательно сохранить резервную копию репозитория 0.9.6.

SQL

1. Откройте Supabase → SQL Editor.
2. Полностью выполните файл:
   supabase/collaboration_upgrade_0.9.7.sql

   Он запускается ПОСЛЕ уже установленных:
   collaboration_upgrade_0.9.5.sql
   collaboration_upgrade_0.9.6.sql

3. Успешный результат:
   Alex Board 0.9.7 fast queue and row object storage installed

КОД

4. Загрузите всё содержимое архива 0.9.7 в корень GitHub-репозитория с заменой старых файлов.
5. Дождитесь успешного GitHub Pages build/deploy.
6. Полностью закройте старые вкладки и откройте сайт заново. Не продолжайте работу в вкладке 0.9.6 после установки SQL.

ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА

1. Откройте одну доску в двух окнах.
2. Быстро напишите 100–200 коротких штрихов.
   Ожидаемое поведение:
   - интерфейс не начинает всё сильнее зависать с ростом очереди;
   - очередь может кратковременно увеличиться, затем должна уменьшаться пакетами;
   - второй участник видит письмо сразу через Ably.
3. Удалите объект → Undo → Redo → Undo.
   Объект должен возвращаться с тем же objectId и тем же слоем.
4. Выделите несколько объектов и переместите их вперёд/назад по слоям.
   Порядок должен совпасть в обоих окнах и после перезагрузки.
5. Отключите интернет, создайте несколько объектов, обновите страницу после восстановления интернета.
   Pending-операции должны восстановиться из IndexedDB и уйти на сервер пакетами.
6. Скопируйте часть урока между досками и отдельно скопируйте всю доску.
7. После 30-секундной страховочной проверки не должно происходить замены всего Canvas.

КАК ПРОВЕРИТЬ SUPABASE

В Table Editor должна появиться таблица:
   board_objects

Один новый штрих должен добавлять/изменять только одну строку этой таблицы.
Поле boards.snapshot не должно переписываться после каждого штриха; оно обновляется только на checkpoint-ревизиях.
