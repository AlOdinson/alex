# Alex Board 1.29

Основа: версия 1.28.1.

## Новый лёгкий формат переноса

Перемещение, масштабирование и вращение больше не сохраняют полный JSON объекта. После завершения жеста создаётся одна компактная операция `transform`, содержащая только:

- стабильный ID объекта;
- `left` и `top`;
- `scaleX` и `scaleY`;
- `angle`, `skewX`, `skewY`;
- `flipX` и `flipY`;
- время и автора изменения.

Длинный Pencil-path, изображение, текст и остальные неизменяемые данные объекта повторно не сериализуются, не клонируются и не отправляются.

## Горячий путь Apple Pencil

В обработчике завершения переноса больше нет:

- `object.toObject()`;
- полного `upsert` перенесённого объекта;
- построения полного snapshot доски;
- обхода всех объектов ради z-index;
- `requestIdleCallback` с поздней тяжёлой сериализацией;
- ожидания Supabase перед началом следующего жеста.

Остаются только расчёт итоговой трансформации выбранных объектов, запись маленькой операции и немедленное освобождение ввода.

## Очередь

- Один перенос группы сохраняется одной логической операцией.
- Пока одна transform-операция подтверждается сервером, новые позиции объединяются в памяти по ID объекта.
- Для каждого объекта сохраняется только последняя позиция; промежуточные положения не раздувают очередь.
- В обычной работе остаётся максимум одна transform-операция на сервере и один объединённый набор последних координат в памяти.
- Принудительная дополнительная операция допускается только перед Undo, Delete, закрытием вкладки или другой операцией, для которой важен строгий порядок.

## Realtime и восстановление

- Live-transform во время движения по-прежнему отправляет лёгкие матрицы для второго участника.
- Финальная durable-операция также остаётся компактной.
- Realtime-получатель применяет координаты к уже существующему Fabric-объекту без его удаления и повторного создания.
- Восстановление из журнала и локального IndexedDB умеет накладывать transform-операции поверх прежнего полного объекта.
- Старые snapshot и старые операции `upsert/delete` сохраняют совместимость.

## Snapshot

Обычный перенос не запускает сборку полной доски. Полный snapshot остаётся только для настоящих изменений содержимого: создания, удаления, изменения текста, стиля или геометрии объекта. Такая компактизация запускается не раньше чем после 30 секунд реального отсутствия ввода и отменяется при новом контакте с доской.

## Дополнительные оптимизации

- Удалён O(N)-обход всей доски для вычисления z-index в начале каждого переноса.
- Групповое применение transform при восстановлении использует карту ID и не выполняет `findIndex` по всей доске для каждого участника.
- Remote transform не разрушает локальное выделение, если изменяются другие объекты; если меняется участник текущего `ActiveSelection`, обёртка временно снимается и корректно восстанавливается.
- Undo/Redo перемещения используют тот же лёгкий transform-путь.
