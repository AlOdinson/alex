# Alex Board 0.9.1 — общая игротека

Совместная онлайн-доска для занятий с GitHub Pages, Supabase и двумя независимыми Ably-потоками: доска и игры.

## Игротека 0.9.1

- кнопка «Игротека» по умолчанию скрыта;
- только владелец показывает или скрывает её последовательностью `→ ← → ←`;
- при закрытии все открытые игры принудительно возвращаются на доску;
- до четырёх участников могут независимо находиться на доске или в общей игре;
- один участник управляет, остальные наблюдают;
- активный игрок добровольно передаёт управление;
- преподаватель может принудительно забрать управление;
- ученики не могут самовольно отбирать управление;
- игровое состояние передаётся 10 раз в секунду, а команды — немедленно;
- одиночная игра не отправляет постоянные игровые состояния;
- на ПК пауза переключается пробелом;
- на мобильных есть экранный джойстик и кнопка паузы сверху слева;
- мобильная камера следует за божьей коровкой и держит её около центра;
- при потере активного игрока через 3 секунды управление получает преподаватель или первый оставшийся участник.

Для игр добавлены Edge Functions `ably-game-token` и `ably-game-control`.
Базовая настройка описана в `INTEGRATION_0.9.0_RU.txt`, исправления 0.9.1 — в `INTEGRATION_0.9.1_RU.txt`.
Новый SQL для 0.9.0 не требуется: достаточно уже выполненного обновления 0.8.1.

## Realtime

- курсор, рисование и перемещение публикуются напрямую без последовательной realtime-очереди;
- частота живых обновлений — до 20 раз в секунду (каждые 50 мс);
- готовое состояние сохраняется в Supabase;
- при сбое Ably остаётся fallback на Supabase Realtime.

## Что исправлено в 0.7.4

- большая вставка показывается на принимающем устройстве одной собранной пачкой, а не по одному объекту;
- частые постоянные операции объединяются в один или несколько крупных запросов Supabase вместо длинной очереди из десятков запросов;
- повторные операции над одним ID внутри пачки схлопываются до последнего состояния;
- удаление передаётся принимающему устройству мгновенным отдельным событием Ably, не ожидая Supabase;
- объектный ластик передаёт удалённые ID маленькими пачками примерно каждые 32 мс;
- удалённый объект защищён временной tombstone-меткой от позднего возвращения старым preview, draw или snapshot;
- быстрые карандашные штрихи сопоставляются с Fabric-path по стартовой точке, поэтому чужой штрих не получает ID соседнего;
- Delete и Backspace удаляют выделенные линии и объекты;
- массовое применение входящих объектов выполняется одним enliven-пакетом и одной перерисовкой.

## Экономия без снижения скорости

- `echoMessages: false`;
- новые точки карандаша передаются дельтами;
- большая группа двигается одной матрицей;
- одинаковые состояния не публикуются повторно;
- курсор во время рисования и движения входит в тот же realtime-пакет;
- временные сообщения не используют Ably History.
