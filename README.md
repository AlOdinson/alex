# Alex Board 1.0.0 — первый стабильный релиз

## Что исправлено

- первый Apple Pencil contact сразу после двухпальцевого zoom больше не теряется;
- завершение zoom восстанавливает ввод лёгкой O(1) функцией без обхода всех объектов;
- Pencil может синхронно закрыть ещё завершающийся gesture до передачи того же pointerdown в Fabric;
- пальцы старого gesture подавляются до отпускания и не запускают zoom внутри Pencil-штриха;
- запоздалый touchend защищён generation и идентификаторами пальцев;
- частичный ластик, один палец, Select, Text, Shape, Line, объектный ластик, пипетка и права доступа сохранены;
- SQL и серверная схема не меняются.

Для перехода с 0.9.9 на 1.0.0 новый SQL не нужен. Инструкция: `UPDATE_INSTRUCTIONS_1.0.0_RU.txt`.

# Alex Board 0.9.9 — hotfix Apple Pencil

## Что исправлено

- TouchEvent больше не отменяется целиком во время активного Apple Pencil;
- Palm rejection продолжает работать на уровне PointerEvent, но не блокирует поток самого Pencil;
- Safari pointerId очищается при новом контакте Pencil, чтобы ручка не наследовала ID ранее отклонённой ладони;
- контакт ладони отклоняется только как дополнительный или крупный touch-pointer;
- удалена эвристика, которая могла ошибочно считать два соседних маленьких штриха одним дубликатом;
- точное удаление preview по `creationSessionId` сохранено;
- однопальцевое рисование и двухпальцевое перемещение без Pencil сохранены;
- SQL и серверная схема 0.9.7 не меняются.

Для перехода с 0.9.8 новый SQL не нужен. Инструкция: `UPDATE_INSTRUCTIONS_0.9.9_RU.txt`.

# Alex Board 0.9.5 — безопасная страховочная синхронизация

Совместная онлайн-доска для занятий с GitHub Pages, Supabase и двумя независимыми Ably-потоками: доска и игры.

## Доска 0.9.5

- Ably мгновенно показывает живые изменения;
- Supabase сохраняет каждое завершённое логическое действие отдельной атомарной ревизией;
- старая полная проверка каждые 12 секунд заменена получением пропущенных операций каждые 30 секунд;
- Ably и страховочная проверка используют одну последовательную очередь;
- ревизия повышается только после успешного применения всей операции;
- групповые действия, Undo/Redo и очистка не разбиваются на части;
- objectId сохраняется при перемещении и групповом преобразовании;
- блокировки активных объектов продлеваются автоматически;
- длинный журнал загружается постранично;
- изображения с временно недоступным файлом остаются placeholder с тем же objectId и догружаются отдельно;
- обычная проверка не заменяет Canvas полным JSON;
- полный snapshot остаётся только для первого открытия и аварийного восстановления;
- редкая проверка целостности выполняется не чаще одного раза в 5 минут;
- при серверном конфликте последующие записи ставятся на паузу, серверное состояние восстанавливается, а оставшиеся локальные действия накладываются заново.

### Обязательная установка SQL

Перед деплоем выполни:

```text
supabase/collaboration_upgrade_0.9.5.sql
```

Edge Functions и секреты Ably этим обновлением не меняются. Подробности находятся в `UPDATE_INSTRUCTIONS_0.9.5_RU.txt` и `INTEGRATION_0.9.5_RU.txt`.

## Предыдущие изменения

Совместная онлайн-доска для занятий с GitHub Pages, Supabase и двумя независимыми Ably-потоками: доска и игры.

## Доска 0.9.4 — одиночный режим без action-трафика Ably

- Fabric Canvas продолжает работать локально с обычной частотой отрисовки устройства, включая 60 FPS;
- пока в канале доски находится один участник, курсор, живое рисование, перемещения, блокировки, preview, режим инструмента и другие временные события не публикуются;
- постоянные операции по-прежнему сохраняются в Supabase после завершения действия;
- Presence остаётся подключённым, чтобы сразу определить вход второго участника;
- при появлении второго участника realtime-передача включается немедленно, ожидающие записи сохраняются и отправляется один запрос проверки ревизии;
- после выхода последнего удалённого участника realtime остаётся включённым ещё 3 секунды на случай краткого переподключения, затем снова становится тихим;
- несколько вкладок или устройств считаются несколькими участниками и автоматически включают совместный режим.

Для 0.9.4 не нужны новый SQL, новые секреты или повторное развёртывание Edge Functions.

## Игротека 0.9.3

### Интерфейс игры 0.9.3

- блоки «Жизни» и «Путь» занимают только необходимую ширину на компьютерах, iPad и телефонах;
- панель участников игровой комнаты стала на 40% прозрачнее;
- игровая логика, 10 Гц синхронизация и права управления не изменены.

- кнопка «Игротека» по умолчанию скрыта;
- только владелец показывает или скрывает её последовательностью `→ ← → ←`;
- при закрытии все открытые игры принудительно возвращаются на доску;
- до четырёх участников могут независимо находиться на доске или в общей игре;
- один участник управляет, остальные наблюдают;
- активный игрок добровольно передаёт управление;
- преподаватель может принудительно забрать управление;
- ученики не могут самовольно отбирать управление;
- игровое состояние передаётся 10 раз в секунду, а команды — немедленно;
- одиночная игра не отправляет постоянные игровые состояния;
- на ПК пауза переключается пробелом;
- на мобильных есть экранный джойстик и кнопка паузы сверху слева;
- мобильная камера следует за божьей коровкой и держит её около центра;
- при потере активного игрока через 3 секунды управление получает преподаватель или первый оставшийся участник.
- поле состояния воды в игровом HUD скрыто;
- надпись наблюдателя перенесена к нижнему краю;
- имена участников служат кнопками передачи управления: активный игрок передаёт добровольно, а преподаватель назначает любого участника в любой момент;
- в мобильной верхней панели справа закреплены иконки экспорта и отправки ссылки на доску.

Для игр добавлены Edge Functions `ably-game-token` и `ably-game-control`.
Базовая настройка описана в `INTEGRATION_0.9.0_RU.txt`, дальнейшие изменения — в `INTEGRATION_0.9.1_RU.txt` и `INTEGRATION_0.9.2_RU.txt`.
Новый SQL для 0.9.0 не требуется: достаточно уже выполненного обновления 0.8.1.

## Realtime

- при одном участнике действия доски не публикуются через Ably; используется только тихое Presence-подключение и сохранение результата в Supabase;
- при двух и более участниках живой realtime включается автоматически;
- курсор, рисование и перемещение публикуются напрямую без последовательной realtime-очереди;
- частота живых обновлений — до 20 раз в секунду (каждые 50 мс);
- готовое состояние сохраняется в Supabase;
- при сбое Ably остаётся fallback на Supabase Realtime.

## Что исправлено в 0.7.4

- большая вставка показывается на принимающем устройстве одной собранной пачкой, а не по одному объекту;
- частые постоянные операции объединяются в один или несколько крупных запросов Supabase вместо длинной очереди из десятков запросов;
- повторные операции над одним ID внутри пачки схлопываются до последнего состояния;
- удаление передаётся принимающему устройству мгновенным отдельным событием Ably, не ожидая Supabase;
- объектный ластик передаёт удалённые ID маленькими пачками примерно каждые 32 мс;
- удалённый объект защищён временной tombstone-меткой от позднего возвращения старым preview, draw или snapshot;
- быстрые карандашные штрихи сопоставляются с Fabric-path по стартовой точке, поэтому чужой штрих не получает ID соседнего;
- Delete и Backspace удаляют выделенные линии и объекты;
- массовое применение входящих объектов выполняется одним enliven-пакетом и одной перерисовкой.

## Экономия без снижения скорости

- `echoMessages: false`;
- новые точки карандаша передаются дельтами;
- большая группа двигается одной матрицей;
- одинаковые состояния не публикуются повторно;
- курсор во время рисования и движения входит в тот же realtime-пакет;
- временные сообщения не используют Ably History.
