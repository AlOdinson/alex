# Alex Board 1.32.0 — Authoritative operation log v8

## Единое подтверждённое состояние

- Supabase назначает каждой логической операции ровно одну последовательную ревизию.
- Получатели узнают о ревизии из таблицы `board_action_heads_v8`, даже если устройство автора закрылось сразу после commit.
- Пропущенные, переставленные и повторённые realtime-пакеты восстанавливаются по журналу.
- Старые RPC записи `v7/v5/v4` отключаются SQL-миграцией. Клиент не продолжает работу через несовместимый fallback.

## Одновременные действия

- Перемещение сохраняется лёгкой `transform`-операцией.
- Стиль, текст и содержимое изменяются точечным `patch`, поэтому цвет и координаты одного объекта не затирают друг друга.
- Удаление является tombstone: более поздний preview или patch не воскрешает объект.
- Большая вставка загружается частями, но подтверждается одной атомарной ревизией.
- Undo/Redo создают новые точечные серверные операции и не откатывают чужие независимые поля.

## Производительность

- Локальный Fabric и быстрые live-preview Pencil/transform не ждут сервер.
- Серверная работа пропорциональна затронутым объектам конкретного действия.
- Активная синхронизация не выполняет периодического полного обхода или сравнения всей доски; снимок собирается отдельно только после реального бездействия как стартовый кэш журнала.
- Текстовый preview остаётся с debounce 120 мс, transform/draw — 50 мс, object eraser — 32 мс.

## Обязательная установка

Перед публикацией клиента один раз выполните в Supabase SQL Editor:

`supabase/authoritative_log_v8.sql`

Клиент 1.32.0 намеренно не откроет серверную доску без этой миграции.

## Проверка

- Production-сборка Vite.
- Старые convergence-fence тесты.
- Детерминированная симуляция четырёх клиентов, больших атомарных вставок, пропусков, перестановки, повторов, удаления и одновременных patch/transform.
