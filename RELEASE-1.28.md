# Alex Board 1.28

Основа: версия 1.27.1.

## Завершение перемещения Apple Pencil

- Один физический перенос Apple Pencil создаёт ровно одно завершение трансформации. Повторный совместимый `mouse`-хвост Safari отбрасывается по идентификатору жеста и по итоговой матрице объектов.
- В обработчике `object:modified` больше не сериализуется целиком карандашная линия, изображение или группа. На отпускании сохраняются только ID, итоговая матрица и z-index.
- Z-index всех объектов вычисляется один раз в начале трансформации и повторно используется для live-transform, Undo и сохранения.
- Завершение live-transform больше не уничтожает необходимые данные до `object:modified`.
- При начале переноса существующие объекты больше не проходят повторно через тяжёлый `markObject()` и массовый `setCoords()`.

## Снятие выделения

- Клик Apple Pencil в пустоту больше не запускает второй ручной цикл обновления после `selection:cleared`.
- При снятии большой группы не восстанавливаются синхронно методы контролов у каждого бывшего участника. Они восстанавливаются лениво только тогда, когда конкретный объект снова становится активным.
- UI выделения обновляет только активный объект или оболочку `ActiveSelection`, а не прошлую и текущую группу целиком.
- Чтение общих параметров выбранных объектов перенесено после кадра отрисовки, поэтому рамка исчезает прежде, чем React пересчитывает панель свойств.

## Очередь и сохранение

- Итоговые координаты Pencil сначала складываются в компактную таблицу `Map<objectId, latestTransform>`: повторные переносы того же объекта заменяют предыдущие, а не создают новые задания.
- Полный JSON объекта формируется только после полного завершения Pencil-контакта, защитного окна Safari и свободного кадра браузера.
- На Safari без `requestIdleCallback` сохранение ждёт две отрисовки, чтобы не блокировать перенос или следующий клик.
- Все объекты одного группового переноса отправляются как одно логическое действие, поэтому один жест не превращается в десятки элементов очереди.
- Пока сервер подтверждает одно обычное действие перемещения, последующие перемещения объединяются в последнее состояние. В нормальном режиме в очереди остаётся не более одного Pencil-transform; принудительный второй элемент разрешён только для Undo/Delete, скрытия вкладки или другого действия над теми же объектами.
- Несвязанные действия над другими объектами больше не заставляют немедленно сериализовать отложенный перенос.
- Уже вычисленный размер JSON передаётся через realtime и repository, поэтому один и тот же большой объект не проходит несколько `JSON.stringify()` подряд.
- При `pagehide`, скрытии вкладки и потере фокуса последнее отложенное положение принудительно ставится на сохранение.

## Совместимость

- Форматы объектов, snapshot и существующие RPC Supabase не изменены; миграция базы не требуется.
- Мышь и палец сохраняют прежнее поведение.
- Live-transform для второго участника остаётся мгновенным, а durable-сохранение выполняется отдельно и не блокирует главный поток ввода.
